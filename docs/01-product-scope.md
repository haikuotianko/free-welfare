# 01 产品范围

## 1. 背景

微信小程序里有大量“签到得积分、积分换商品/券”的会员活动。单个小程序的操作很简单，但分散在多个小程序、多个账号上时，会出现：

- 每天要逐个打开小程序签到，容易忘；
- 不知道积分什么时候过期、还能换什么；
- 限量商品/券开抢时间不固定；
- 每个小程序的登录方式、接口、签名都不一样；
- 已有青龙脚本分散，缺少统一配置、日志、失败重试和版本管理。

本项目是一个**自托管工具**：每个使用者部署自己的实例，连接自己的 YYB，按订阅源安装审核过的脚本。

## 2. 定位

### 2.1 是

- 个人/小团队自托管的签到与积分管理工具。
- 开源项目：别人可以自己部署、自己改、自己扩展脚本。
- 脚本订阅平台：从 GitHub 订阅源同步脚本，支持版本、hash、回滚。
- 社区脚本仓库的“运行时”：其他用户通过 PR 提交脚本，维护者审核后发布。
- PC 优先、移动端友好的 PWA：桌面端完整管理，手机端完成日常操作。

### 2.2 不是

- 不是公开注册的多用户 SaaS。
- 不是每个用户一个 YYB 的托管平台；YYB 由使用者自己部署。
- 不是任意脚本上传/执行市场；官方源审核，自定义源强警告且只能使用 `ctx` API。
- 不是“保证抢到”的工具；只做提前准备和按时请求。

## 3. 目标

### 3.1 核心目标

1. **账号管理**：同步自己 YYB 里的微信账号、状态、有效期，失效时引导重扫。
2. **应用管理**：以小程序为单位管理 AppID、应用信息、多个功能脚本、绑定账号和能力。
3. **分析资产**：每个小程序有解包/接口/积分/加密文档，写脚本只读文档即可。
4. **自动化任务**：登录、签到、同步积分/商品/活动；后续兑换、抢购。
5. **积分资产**：余额、获取记录、有效期；优先使用即将过期的积分。
6. **脚本订阅**：从 GitHub 源安装/更新/回滚脚本；显示审核状态和版本。
7. **脚本结构**：一功能一脚本（注册/签到/积分/商品/活动）+ 公共模块（auth/crypto/http）。
8. **PC 优先、移动端友好**：桌面端看全局/批量操作；手机一屏看清今天要做什么、哪里有即将过期的积分。
9. **可运维**：Docker Compose、数据库备份、健康检查、结构化日志、Server酱通知。
10. **可贡献**：脚本仓库有统一 manifest、CI 校验、审核流程，别人能提交新脚本。

### 3.2 首期范围（MVP）

- 单管理员、1-3 个微信账号。
- 一个脚本订阅源（项目自己的 GitHub 仓库）。
- 首个应用：**三福会员**，按一功能一脚本拆分：
  - `common/auth`：登录/会话（code → sid、ensureSession）
  - `login`：手动登录/测试
  - `sign_in`：每日签到
  - `points`：积分余额/即将过期/截止日期（各应用可自定义名称）
  - `register`/`products`/`activities`：待接口确认
- 商品/活动读取：如果解包/抓包能补到接口，首期一起做；否则先留能力位。
- 任务调度、手动执行、运行日志、失败通知。
- Server酱通知。
- ARM64 NAS Docker Compose 部署。
- 移动端首页、账号、积分、脚本、运行详情。

### 3.3 后续范围

- 商品列表/兑换/活动。
- 积分批次与过期提醒。
- 限时抢购/补货监控。
- 更多小程序脚本（社区 PR）。
- 多订阅源、脚本版本固定/回滚。
- 可选的更强沙箱（Deno/容器）。
- 家庭共享（可选，非多租户）。

## 4. 非目标

| 非目标 | 原因 |
| --- | --- |
| 公开注册、多租户 SaaS | 账号归属、合规、滥用、运维复杂度高；当前定位是自托管 |
| 批量注册、接码、伪造手机号 | 违反平台规则，法律与封号风险高 |
| 绕过验证码、风控、设备指纹 | 不提供对抗能力；遇到验证码转人工 |
| 自动支付、代付、绑卡 | 资金安全风险高；需要人工确认 |
| 保证抢购成功 | 只能提高准备与执行效率 |
| 执行任意 Node 代码 | Node `vm` 不是安全边界；官方源审核，custom 禁用 dependencies/require |
| 伪造微信/业务返回值 | 失败就如实报告 |

## 5. 用户与角色

### 5.1 部署者/管理员

- 有服务器/NAS，能跑 Docker。
- 部署自己的 YYB，扫码添加微信账号。
- 配置平台、安装脚本、绑定账号、看日志。
- 可选：给家人/朋友开只读或操作账号（后续，非首期）。

### 5.2 脚本贡献者

- 在 GitHub 脚本仓库提 PR。
- 提供 manifest、适配器、测试/脱敏样本。
- 维护者审核接口、权限、敏感信息、幂等性。
- 合并后 CI 生成新版本索引，平台用户可更新。

## 6. 核心用户旅程

### 6.1 首次部署

1. `docker compose up -d`。
2. 打开 Web，创建管理员账号。
3. 填 YYB 地址 + `YYB_INTEGRATION_TOKEN`，测试连接。
4. 在 YYB 控制台扫码添加微信账号。
5. 平台同步账号，显示状态。
6. 创建/选择应用，填写名称、AppID、积分别名。
7. 从订阅源安装登录/签到/积分脚本。
8. 绑定账号，填配置（如需），手动跑一次。
9. 看到签到成功/积分余额，创建每日任务。
10. 配置 Server酱，测试通知。

### 6.2 每日使用

1. 打开手机首页：今日签到 `1/1`，积分 `xxx`，失败 `0`。
2. 看“即将过期积分”（有数据时）。
3. 看“可兑换商品/活动”（有接口时）。
4. 有失败：点进运行详情，看错误分类；需要重扫就跳 YYB。
5. 有脚本更新：订阅页提示，查看 changelog 后更新/回滚。

### 6.3 新增脚本（贡献者）

1. Fork 脚本仓库。
2. 复制模板，填 manifest（AppID、能力、允许域名、配置 schema）。
3. 用 WMPFDebugger/KillWxapkg/抓包定位接口。
4. 实现 `login/sign_in/points/...`，加脱敏 fixture 和测试。
5. 本地用平台 dry-run 验证。
6. 提 PR；CI 校验 manifest/测试/敏感信息；维护者审核。
7. 合并后发布新版本，用户在平台更新。

## 7. 关键术语

| 术语 | 含义 |
| --- | --- |
| YYB | YYB-Go-Enhanced，负责微信扫码授权、保存凭据、按 AppID 取 `wx.login` code |
| `wx.login` code | 微信小程序的一次性登录凭证，短期有效，只能使用一次 |
| 业务 token / sid | 小程序后端用 code 换来的登录态 |
| 应用 / Site | 一个目标小程序，核心标识是 `app_id` |
| 功能脚本 / Action | 一个功能（注册/签到/积分/商品/活动），一个脚本 |
| 公共模块 / Common | 登录/会话、加密/签名、HTTP 等复用代码，不直接运行 |
| 绑定 / Binding | “微信账号 + 应用 + 功能脚本 + 配置”的安装实例 |
| 任务 / Task | 绑定上的一个可调度能力，如每日签到、同步商品 |
| 运行 / Run | 任务的一次执行，包含日志、结果、错误分类 |
| 订阅源 / Source | GitHub 脚本仓库，平台从它同步索引和版本 |
| 积分批次 / Point Lot | 一次积分发放及剩余额度、过期时间 |

## 8. 约束与风险

### 8.1 平台与合规

- 仅操作本人已授权的账号。
- 不绕过验证码/风控/排队/限购；遇到人工验证暂停并通知。
- 官方源脚本审核后安装；自定义源强警告，`custom` 脚本只能用 `ctx` API。
- 遵守目标平台服务条款；账号被限制/封禁的风险由使用者承担。

### 8.2 技术

- 小程序接口会变，脚本要版本化、可回滚、可快速修复。
- `wx.login` code 一次性、短时效，不能缓存复用。
- YYB 授权可能失效，需要重新扫码；平台要识别 `409` 并引导。
- 业务 token 可能过期；脚本要能自动重登，但不能无限重试。
- Node `vm` 不是安全边界；官方源靠审核，自定义源禁用 `dependencies/require`，未来更强隔离要上 Deno/容器。
- ARM64 NAS 资源有限，Postgres + Node 要控制内存。
- 部分积分/商品数据只在页面展示，接口不返回；只能估算并标记。

### 8.3 脚本供应链

- 订阅源被投毒是最大风险；必须：维护者审核、CI 校验、hash 固定、版本回滚。
- 脚本不能读取宿主机敏感文件/环境变量；worker 只注入最小上下文。
- 脚本网络请求走平台代理，限制允许域名，记录审计。
- 自定义源标记 `custom`，UI 强警告；不允许 `dependencies/require`，只能用 `ctx` API。

## 9. 成功标准

首期验收：

- [ ] ARM64 NAS 上 `docker compose up -d` 能启动。
- [ ] 首次打开能创建管理员并登录。
- [ ] 能连接自己的 YYB，同步账号和状态。
- [ ] 能安装“登录/签到/积分”脚本并绑定账号。
- [ ] 签到成功，重复运行不会重复签到。
- [ ] 能看到积分余额/连签天数（有接口时含商品/活动）。
- [ ] 手机端首页能看到今日状态、失败原因、余额。
- [ ] 任务可定时、手动跑、停、看实时日志。
- [ ] 失败通过 Server酱通知，日志不泄露 code/sid/手机号。
- [ ] 脚本可更新/回滚，版本和 hash 可查。
- [ ] 新增同类小程序主要写脚本，不改平台核心。
